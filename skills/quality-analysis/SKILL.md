# 质量分析

## 适用条件

用户询问图片是否异常、某批次为何异常、依据哪项标准或应采取什么措施时使用。

## 执行步骤

1. 对所有输入调用 `get_asset`。文档和表格先调用 `parse_asset`。
2. 图片检测调用 `inspect_images`。人工复核试验使用 `review_test`，上机记录使用 `machine_test`。
3. `inspect_images` 会等待检测终态并直接返回结果；仅当返回 `wait_timed_out=true` 时再调用 `get_job`。保留模型版本、阈值、分数和原机器结论。
4. 使用 `search_evidence` 检索检验规范、历史记录与处理措施。
5. 使用 `query_quality_graph` 查询产品→批次→工序→异常→标准/措施的关联路径。
6. 证据不足时缩小关键词再次检索；仍不足则标明缺口。
7. 用 `get_trace` 返回执行记录以便审计。

## Nexent 调用格式

调用工具时只输出一个可执行的 `<code>...</code>` 块，在其中使用变量接收工具结果并 `print()`。执行完成后，在下一步把打印内容作为文本读取并形成结论；不要继续对打印结果使用 `[]`、`.get()` 或 `json.loads()`。禁止输出 DSML、内部调用标签或未执行的伪代码。

## 输出要求

先给检测结论，再给模型版本和数值，随后列出文档证据、图谱路径、建议和不确定项。不得把 `machine_test` 的机器预测直接作为学习标签。

节点数、边数、路径数、证据数和模型结果数必须逐字采用工具返回值，不得估算。只有在返回的边 ID 确实重复时才能报告重复边；不能把不同证据产生的多条关系描述为数据冗余。文档证据与 AOI 检测结果必须分开陈述，`inspections` 为空时明确说明尚无图像检测结论。
